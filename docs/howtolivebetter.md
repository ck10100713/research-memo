## 一句話

一本按「性價比」算帳的人生指南:每條建議都回答「要花掉什麼(錢、時間、精力、毅力)」和「能換回什麼(壽命、金錢、時間精力、人身自由)」,證據只引期刊論文和官方文件。

## 內容

- 34 節、767 條,A 級 495、B 級 220、C 級 52,88 條標了「爭議」,2,531 個原始文獻連結
- 範圍很廣:不要早死、慢性病、急救、省錢理財、反面清單(不用買的保健品和體檢套餐)、沒錢時能領什麼、法律紅線、程式設計師容易踩的刑責、創業與做平台要辦的證照、勞動和工傷、租屋買房、看病、婚育、老人、身後事、出國留學、殘疾之後
- `docs/` 另有九篇長文(結婚划不划算、家庭應急裝備清單、被裁之後先做什麼……)和 `docs/核实记录/`,每條的查證過程都留著
- 法律、醫保、社保都照**中國大陸**現行規定寫,台灣讀者能直接用的主要是健康、急救這類 A 級條目

### 條目格式

```markdown
### 5. 把家里的食盐换成低钠盐(钾盐)
<!-- 成本标签: 钱=少 时间=少 毅力=否 收益=中 口径=死亡率 -->
- 成本:一袋比普通盐贵几元……
- 说人话:……五年内死亡的概率低约 12%,中风低约 14%。
- 收益:随机试验,20995 人,跟踪 4.74 年……RR 0.88……
- 证据等级:A
- 来源:Neal B 等 (2021). NEJM. https://doi.org/10.1056/NEJMoa2105675
- 备注:争议。试验对象是高危老人……
```

- 標題一律動詞開頭
- 「說人話」是給只看一行的讀者,不准出現 HR/RR/隨機/樣本量,也不准出現收益欄沒有的數字
- 標題下那行 HTML 註解是給機器讀的標籤,GitHub 上看不到;可選的 `人群=` 只有 7 個值(怀孕、婴幼儿、孩子、老人、35岁、60岁、女性)

### 性價比怎麼算

`index.html` 裡兩行(第 614 行、第 1034 行):

```js
const COST_W = { money:{'0':0,'少':1,'多':2}, time:{'少':0,'中':1,'多':2}, will:{'否':0,'些':1,'是':2} };
e.ratio = e.level === '大' ? (e.cs === 0 ? '极高' : (e.cs <= 2 ? '高' : '一般'))
        : e.level === '中' ? (e.cs === 0 ? '高' : '一般') : '一般';
```

三項成本相加。收益大且零成本是「極高」(目前 123 條)。四種口徑各算各的,不互相換算。作者自己也承認,這個分檔照書的標準只算 C 級。

受益人另外分四檔:自己 > 配偶直系 > 朋友同事 > 陌生人。寫到陌生人那檔時,被訛、被捲進案子的風險要跟好處一起寫。

## 技術架構

| 部分 | 做法 |

| 資料 | `README.md` + `book/*.md` 就是資料庫,沒有後端 |

| 產物 | CI 每次更新自動產出 EPUB、PDF(pandoc + typst)、離線單檔 HTML、Anki 牌組,放在固定的 `epub-latest` Release |

### 把寫作規範變成 CI

`.github/workflows/book.yml` 的檢查 job:

- **說人話檢查** `check-plain.mjs`:說人話超過 120 字、出現統計縮寫或研究設計詞、出現「另一頭」「產出」這類要讀者自己翻譯的比喻,就失敗。起因是 issue #42 讀者說「AI 味太重」
- **交叉引用檢查** `check-refs.mjs`:全書幾百處「見第 X 條」只記條號,插一條新的進去後面都會位移,而且位移後通常還在範圍內,查越界抓不到。所以它把每處引用實際指到的標題寫進 `docs/引用对照.md`,看 diff 就知道哪處被撞歪。這個 job 故意不掛在 build 上,引用壞了不擋電子書發布
- **統計數字檢查** `sync-stats.mjs --check`:README、檢索頁、OG 圖上的條目數和 A 級數過時就紅
- **失效連結** `links.yml`:每週一跑,只有 404、410、DOI 查無此號才要修

### CLAUDE.md

整份規則都附「日期 + 起因」,例如「2026-09-21 用戶說『有些人說是 AI 生成的垃圾看不懂』」。內容包括:

- 一句只說一件事、30 字上下、最長 50 字,當天把全書句子平均長度從 66 字降到 29 字
- 反 AI 腔清單:元敘述、段尾升華句、連用「也就是」、電報體、空轉加強詞
- 改寫以保真優先:否定、範圍、條件是內容不是包裝,第一輪誤刪的 23 句事後放回去
- 只收一手媒體報道的五個條件(只證明「發生過」、數字不取自報道、要附 web.archive.org 存檔……)
- 「法律支持你」的條目必須寫過程成本:要不要打官司、審限多久、律師費誰出

`AGENTS.md` 只有兩句,把「改書」和「用書回答問題」分別導到 CLAUDE.md 和 SKILL.md。

### life-decision-guide skill

Claude Code / Codex 都能裝,裝上後問「替朋友擔保簽不簽」,它會:

1. 先判斷要不要立刻停下:急症先講 120,有自殺念頭先給熱線,已經進入法律程序就指去第 8 節
2. 本機沒有正文就 `git clone --depth 1`,取不到就照實說,不憑記憶複述
3. 從 README 那張「問題 → 節」對照表挑 1 到 3 節,用 grep / sed 抽出整條
4. 排序前當場 `grep` 出 `index.html` 的那兩行公式照著算,不准憑記憶寫
5. 答覆附「第 X 節第 Y 條(標題關鍵詞)」,書裡沒寫的要明說是常識

## 值得注意的地方

1. **用 Claude Code 寫可核對的長篇內容,這是很完整的範例**。重點在於每次讀者抱怨都會變成一條帶日期的規則,能機器檢查的就再做成 CI,所以文風和引用不會寫著寫著就退化回去
2. **Markdown + HTML 註解當結構化資料**:GitHub 上讀起來是一般文件,前端照樣能篩選,不用另外維護 JSON
3. **把書包成 skill 的寫法可以直接參考**:目錄表當路由、grep 當檢索、「沒查到就別答」當護欄,不需要向量資料庫
4. **限制**:法規只適用中國大陸;性價比分檔是作者的判斷;repo 裡有贊助廣告(`ads/`、`tools/ad-mcyyy*.html`)
5. 社群翻譯有英、俄、西、葡、阿、印尼、越南語,但都由別人維護,可能落後中文原文
